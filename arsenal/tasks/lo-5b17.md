## What it draws

A hierarchy drawn as concentric rings of sectors, with each label read from the
centre outward (radial, rotated). The reference is the "emotion wheel" (*La roda
de les emocions*): a small set of top-level categories at the centre, each
splitting into sub-categories in the next ring, those into leaves in the outer
ring. A sector's angular span is the sum of its children's spans; **every leaf
gets an equal angle** — so the geometry is derived entirely from the tree and
the JSON has no coordinate, angle or weight fields.

This is a new rendering family. It is NOT `pie` (flat single ring), NOT `rings`
(nested *containment*, scopes inside scopes — no sectors), and NOT `clock`/
`mindmap` (radial but not ring-subdivided). Nothing existing subdivides a ring
by its parent's sectors.

## Design decisions (settled with the owner)

- **Kind name:** `sunburst`.
- **Angles:** equal per leaf; a parent spans its children. Tree only, with no
  coordinate, angle or weight field. (Weighting was considered and rejected to
  keep refusals simple and the geometry-field refusals intact.)
- **Depth:** capped at **3 rings** (3 levels of nodes). Enforce with a
  readability budget in `docs/format.md` (a max per ring and a total-node cap,
  refused before the fit limit, like every other kind). Deeper nesting is a
  `DocumentError`, not a `FitError`.
- **Centre:** an **optional** `center` hub label in the middle (the overall
  topic). When present it is the root and the 3 rings are its descendants; it is
  the hub, not counted as a ring. When absent, the top-level nodes form the
  innermost ring (its centre circle split into sectors), as in the emotion wheel.

## JSON shape (sketch — finalise in the proposal)

```json
{
  "$schema": "...drawspec-v1.schema.json",
  "version": 1,
  "kind": "sunburst",
  "title": "...",
  "description": "...",
  "center": "optional hub label",
  "nodes": [
    {"text": "IRA", "children": [
      {"text": "Loco", "children": [{"text": "Agresivo"}]}
    ]}
  ]
}
```

A node is `{text, children?}`. No `id`/`x`/`y`/`size`/`angle`/`weight` — all
refused with a pointing error, as drawspec does everywhere.

## The hard part — the drawing

The JSON is trivial; layout is the whole job. Build it as a parametric radial
template (like `cycle`/`clock`), NOT the layered graph engine:

1. **Angles** from the tree: assign each leaf an equal slice of 360°; a parent's
   span and mid-angle follow from its leaves. Deterministic ordering.
2. **Ring radii / widths are auto and need not be equal.** Size each ring's
   radial band from the text it must hold at that radius (longer labels and
   outer rings that fan wider need more band). Inner rings are narrower, outer
   wider — matching the example. Derive, never accept, widths.
3. **Radial rotated labels, shrink-to-fit.** Each label is rotated to its
   sector's mid-angle and read outward; on the left half (90°–270°) flip 180° so
   it is never upside down. Pick the largest font (a theme max) at which the word
   fits the available chord × band; step down per label for longer words, with a
   theme floor below which it is a `FitError`. Reuse `text.measure`; do NOT wrap
   mid-word for these radial labels — shrink instead.
4. Sector arcs via `Path`; colours and the centre hub from the theme. Keep the
   greyscale/contrast invariants the other kinds hold.

## Acceptance gate

`sunburst_upside_down_label_count == 0`

Every label is read outward and never upside down; depth beyond 3 rings is a
`DocumentError`; a label that cannot meet the font floor is a `FitError`; no
coordinate/angle/weight field is accepted.
