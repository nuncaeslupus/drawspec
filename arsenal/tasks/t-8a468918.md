**Where:** `src/drawspec/export.py:64-67, src/drawspec/export.py:101-131, src/drawspec/mcp.py:346-356`

### Finding
MAX_SCALE exists 'because a typo would allocate gigabytes', but width/height (document fields and CLI/MCP overrides) have no upper bound, so the same allocation is reachable through them: an MCP caller can exhaust server memory with one render_document call.

### Evidence
render_png(flow example, scale=8): width/height 640x400 -> 134 MB RSS; 4000x4000 -> 576 MB, 3.5 s; 8000x8000 -> 1102 MB, 7 s. Larger widths extrapolated, not run.

### Suggested direction
Cap the pixel area (width*scale x height*scale) in render_png and refuse with the largest allowed size.
