### Finding
Budgets bound the number of entries but not the size of any string. Wrapping/fitting a label takes about 2.7 ms per word across the fit attempts, so one 40 KB label takes 22 s before the inevitable FitError, and a 1 MB label about ten minutes. The MCP handler renders synchronously inside the async event loop, so the server answers nothing (not even pings/cancellation) meanwhile.

### Evidence
Flow example with nodes[0].text='word '*N: N=500 -> 1.42 s, N=2000 -> 5.56 s, N=8000 -> 21.86 s (all end in FitError). An 8000-char unbreakable word is echoed in full inside the FitError message (8666 chars).

### Suggested direction
Refuse text beyond a generous per-field length in validation (cheap, located), truncate quoted labels in messages, and run rendering in a worker thread with a timeout in the MCP server.
