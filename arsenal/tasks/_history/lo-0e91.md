The oldest item on the consumer's list that is not closed. It is `gap4` on two
of their sheets — **39** `devops-cicd-contenedores-y-kubernetes` and **44**
`gestion-de-capacidad-y-disponibilidad` — and 44 is still `blocked` on it after
five rounds.

Checked against `main` rather than assumed:

```
// { "from": "g", "to": "b" } where g is a declared group
/edges/0/from: 'g' is not the id of any node in this document
```

Refused by name rather than accepted-and-ignored, which is the format's own rule
working correctly. The gap is that there is nothing to say instead.

**What the source draws.** A relation that belongs to the whole container, not
to any one box inside it: a monitoring platform that observes *the cluster*, not
one pod of it; a capacity report produced by *the service*, not by one of its
components. Drawn from a member, the diagram says something narrower and wrong —
and picking which member is a coordinate decision, which is the thing an author
must not have to make.

**What already exists to build on.** `kinds/containers` has `Frame`, which
carries the group's extent; `border_obstacles` already knows a frame's border as
geometry an edge must cross; and `crossed` already lifts an edge between two
buried nodes to the level that contains both, for ranking. So the frame is
already a box with an extent and a border — the missing piece is letting a
routed edge anchor on it, and letting the schema name it.

Two things to decide rather than assume:

* **Ranking.** A group is laid out as one node of its size in its parent's
  layout, so an edge to the group can rank against that. An edge to a group from
  *inside* it is a different question and is probably a refusal.
* **The anchor.** An edge to a box meets its border; a frame's border is the
  same shape, but the caption tab occupies a corner of the top edge and already
  keeps a rank gap under it for an arriving arrow (see `caption_obstacle`).

## Acceptance gate

`{"from": "<group id>", "to": "<node id>"}` validates, routes, and draws an
arrow anchored on the frame's border — and the reverse direction too. An edge
naming an id that is neither a node nor a group is still refused by name, and an
edge between a group and a node inside it is refused with a message that says
why. Sheets 39 and 44 can then be redrawn without picking an arbitrary member.

```bash
uv run pytest -q tests/test_kinds_containers.py tests/test_routing.py tests/test_schema.py
```

## Tests

`tests/test_kinds_containers.py` — an edge to a group anchors on the frame, not
on a member; the self-containment case is refused; the id-resolution error still
names the field. `tests/test_schema.py` — the id space for `from`/`to` now
includes group ids, and the published JSON Schema says so.

## Location

`src/drawspec/schema.py` (id resolution for `from`/`to`),
`src/drawspec/kinds/containers.py` (`Frame`, `border_obstacles`, `crossed`),
`src/drawspec/kinds/graph.py` (`_framed`, and the connector set handed to
routing), `src/drawspec/routing.py` (anchoring on a frame border).
