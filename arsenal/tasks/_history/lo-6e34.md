`pyproject.toml` runs mypy with `disallow_untyped_defs`, `disallow_incomplete_defs`
and `warn_return_any` over `src`, `tests` and `tools`, and it passes clean. **None
of that reaches anyone who installs the package.** Without a `py.typed` marker,
PEP 561 says a consumer's type checker must treat `drawspec` as untyped: every
`render_document(...)` call in their code is `Any`, and the strictness this project
holds itself to buys its users nothing.

That is the cheapest credibility win available. Two lines.

## Acceptance gate

`src/drawspec/py.typed` exists, is included in the built wheel, and a consumer
importing `drawspec` gets real types rather than `Any`.

```bash
set -e
test -f src/drawspec/py.typed
uv build --wheel
python3 - <<'PY'
import pathlib, zipfile
wheel = sorted(pathlib.Path("dist").glob("drawspec-*.whl"))[-1]
names = zipfile.ZipFile(wheel).namelist()
assert "drawspec/py.typed" in names, f"py.typed missing from {wheel.name}: {names}"
print(f"py.typed present in {wheel.name}")
PY
```

## Tests

A test asserting the marker file exists and is listed in the wheel, so a future
change to the hatch config cannot silently drop it. `tests/test_packaging.py` is
a reasonable new home — there is no packaging test today.

## Location

`src/drawspec/py.typed` (new, empty), and `[tool.hatch.build.targets.wheel]` in
`pyproject.toml` — hatchling includes package data by default for a `packages`
target, so confirm rather than assume, which is what the gate does.
