There is no outer margin anywhere in the theme. `emit.svg` sets the `viewBox` to
the bounds of the ink widened by half the heaviest stroke, and every family then
adds whatever gutter it happens to add — `kinds/graph._framed` uses
`theme.box.padding.horizontal` (24), `kinds/cycle` uses `padding.top` (10), the
grid and shape families add nothing at all.

Measured over the 33 reference drawings, the top gutter comes to four answers:

| Kind | Top gutter |
|---|---|
| stack, timeline, funnel, pyramid, matrix-raid, chart without an axis label | **0.0** |
| cycle | **10.5** |
| curve, quadrant, chart with an axis label | **21.9 – 22.4** |
| flow, tree | **24.5** |

Nothing clips and nothing collides — this is not a defect, it is an unmade
decision. But put a `timeline` above a `flow` in one document, which the
consumer's temario does on most pages, and the first bleeds to the canvas edge
while the second sits in a 25-unit gutter. The two figures are not framed alike
and a theme has no way to say they should be.

The decision to take: either a drawing is flush and the page supplies its own
padding — in which case `flow`, `tree`, `cycle`, `curve`, `quadrant` and the
axis-labelled charts are the odd ones out — or a figure carries its own gutter,
in which case it belongs in `[canvas]` beside `width` and `caption`, for the
same reason `width` is a theme value: it is what makes two diagrams on one page
look like a pair.

Whichever way it goes, the number stops being emergent. Note that it moves all
33 reference drawings, so the gallery is regenerated with it.

## Acceptance gate

One outer margin, read from the theme, applied in one place, and equal across
every kind. The measurement is the gate: the spread between the largest and the
smallest outer gutter over the reference gallery is zero (within half a stroke),
where today it is 24.5.

```bash
uv run pytest -q tests/ && uv run python tools/clipping.py docs/gallery
```

## Tests

A test that measures the outer gutter of every reference drawing and asserts
they agree — the same shape as the collision and clipping gates, over
`docs/reference/*.json`. Plus a unit test that a theme naming a different margin
gets it.

## Location

`src/drawspec/theme.py` (`Canvas`), `src/drawspec/emit.py` (`ink_inset` and the
`viewBox`), `src/drawspec/render.py` (`centred` is the one place that already
knows about the canvas), and the per-family margins in `kinds/graph.py`,
`kinds/cycle.py`, `kinds/grid.py`, `kinds/shape.py` that it would replace.
