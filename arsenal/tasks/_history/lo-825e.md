## Why this exists

Not from the opos corpus (`docs/kinds-wanted.md` is silent on it — that inventory
only covers the 89 opos diagrams, none of which needed one). It comes from
`integral-job-search`'s `docs/spec-v3/spec-annotated.md`, item 4: *"Can
`drawspec` carry a 2-D scatter? Closed as not blocking, 2026-08-25: drawspec is
the owner's own project, and the owner will add the kind if it is missing."*
The immediate use is a Pareto-frontier view (two measured dimensions, one point
per candidate) — not blocking anything there today, so this is normal priority,
not urgent.

## Open design question — decide before implementing

Is this a new top-level `kind: "scatter"`, or a new mark
(`mark: "point"` / `"scatter"`) on the existing `chart` kind? The mark
vocabulary was explicitly designed to be additive (`docs/kinds-wanted.md`
§"Chart marks" — `"line" | "bar" | "area"`, plus `stack`), which argues for a
mark. But every mark today shares one categorical axis + one value axis, and a
scatter needs **two independent continuous axes** — closer to what `quadrant`
already has.

Look at `quadrant` before designing: `src/drawspec/charts.py` has a `Scale`
class, `_scale_for`, and a `_quadrant_scale` built for two continuous named
axes. `_quadrant_scale` deliberately omits ticks (quadrant answers "which
quadrant", not "what value") — a scatter is the opposite: ticks/values on both
axes are the point, since a reader needs to read approximate coordinates off
it. Reuse the continuous two-axis machinery; don't rebuild it. Point labels
should reuse the chart family's existing overlap-avoidance rather than a new
algorithm — see how `chart` places series/point labels (T14) and how
`quadrant` dodges its own midlines.

A reference document exists and the gallery renders it, docs describe the

## Tests

Write these RED first:

- `test_scatter_plots_points_by_two_continuous_values` — a point at `(x, y)`
  lands at the coordinates its scale predicts, not merely "somewhere in the
  plot"
- `test_scatter_axes_carry_real_ticks_unlike_quadrant` — the thing that
  distinguishes this from `quadrant`; a regression here silently turns the
  scatter back into a quadrant
- `test_scatter_point_labels_avoid_each_other_and_the_axes` — reuse/extend the
  existing chart label-overlap test pattern rather than writing a new one from
  scratch
- Gallery coverage: extend
  `tests/test_gallery.py::test_gallery_covers_every_kind_in_the_vocabulary`
  coverage if `scatter` becomes a top-level kind; if it becomes a `chart` mark
  instead, add the equivalent mark-coverage assertion next to the existing
  `bar`/`line`/`area` ones.
