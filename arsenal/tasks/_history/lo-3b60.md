> **The decision is made. This is now a build task, not a design one.** The three
> options this payload used to open with were tested and settled on 2026-08-17,
> and the reasoning is
> [public on the issue](https://github.com/nuncaeslupus/drawspec/issues/48#issuecomment-5319931957).

## What was decided, and on what evidence

**Bands are out**, and not on grounds of taste. Tried as swimlanes on the exact
document in the issue — `CI` over `build`/`test`/`stage`/`prod`, `Human` over
`approve` — they fail twice:

* **A band's bar spans its members' extent, and ownership is not an extent.**
  With `approve` in the middle of the flow (y=266.55, between stage at 181.7 and
  prod at 351.4), CI's members are discontiguous, so CI's bar is drawn
  `M 238.191 12 L 238.191 388.25` — the full height of the diagram, straight past
  the one step CI does not perform. **The drawing states the opposite of what the
  document says.**
* **A band cannot be named unless its members are wide enough to hold the name.**
  `"A release manager"` over the single `approve` node is refused: *"'manager'
  measures 38.2 at 8.5pt and has no break opportunity that fits 34.6"*. A
  one-step actor is unnameable, and a one-step actor is the case in the issue.

**Real swimlanes are out for now.** Partitioning the layout so each box sits *in*
its owner's lane is the strongest convention for this question and by far the
largest change — a layout constraint, not a decoration, interacting with
direction choice, groups and routing at once. Nothing shows a per-node marker
fails, so it is not justified. Revisit only with evidence that the below is not
enough.

## Build this: `actor` on a node

Free-string, orthogonal to `role`, exactly as the consumer proposed:

```json
{ "id": "approve", "text": "Sign off the release", "actor": "A release manager" }
```

### The design point that unblocks it — read this before touching `theme.py`

Round five's diagnosis was: a node's appearance has six fields (`shape`,
`stroke`, `fill`, `fill_pattern`, `dash`, `stroke_width`), **four are
non-colour**, those four are what the greyscale invariant compares, and all four
are already spent telling the eight roles apart. Therefore ownership needs a
fifth channel, and a fifth channel competes with the four in use.

**That is true and it does not apply, because it assumed ownership must be
encoded as appearance.** It does not have to be. An actor tag carries **the
actor's name**, and text is distinguishable in greyscale by construction — `CI`
does not look like `Human` in any medium. The tag is *added ink that says who*,
not a fifth variation of the box competing with the four that say what kind of
step it is.

Two consequences, both load-bearing:

* `actor` is a **free string, not an enum** — the name is the channel, so
  constraining the vocabulary would remove the thing that makes it work.
* **The greyscale invariant needs no new axis** for actors, and a theme that
  keys actors by colour on top of the name is a decoration, not the mechanism.
  If such keying is added, `theme check` must cover it; if it is not added,
  nothing about `theme check` changes. Prefer not adding it in this task.

### Scope

`node` only. Not `item`, not `cell`. The consumer hit this on `flow`, and this
project opens vocabulary on evidence — there is none yet for the others.

### The part that is actually hard

Not the field and not the theme key — **the space**. A tag drawn outside the box
competes with edge routing and with neighbouring boxes; a tag drawn inside eats
content the box was sized for. Whichever is chosen, the box must be *sized
knowing the tag is there*, the way `[box] lead = "rule"` reserved its band at
measure time rather than drawing into space it had not claimed. `collisions.py`
and `clipping.py` are the checks that will catch getting this wrong, and both
must stay at 0.

## Acceptance gate

**Evidence.** At least two real diagrams redrawn so ownership is visible at a
glance, in `docs/reference/`. One of them should be the issue's release pipeline,
because it is the document the request was written from. A mechanism with no
drawing behind it is the thing `docs/kinds-wanted.md` exists to prevent.

**The invariants still hold**, greyscale included.

```bash
set -e
uv run python -m drawspec.cli theme check default
uv run pytest -q
uv run python tools/collisions.py docs/gallery
uv run python tools/clipping.py docs/gallery
```

Regenerate the gallery first (`make gallery`); both checkers must report **0**,
and the suite must stay green.

## Tests

Whatever is added needs the treatment `[box] lead = "rule"` got:
`tests/test_theme.py` for the invariant, a kinds test for the geometry, and a
reference document the gallery renders. The field means `make docs && make
schema`, and the generated artefacts land in the same diff.

## Location

`src/drawspec/schema.py` (the field), `src/drawspec/theme.py` (the tag's
geometry keys), `src/drawspec/geometry.py` and `src/drawspec/kinds/common.py`
(sizing and drawing), `src/drawspec/kinds/graph.py` (passing it through),
`docs/reference/`, `docs/guide.md`.
