### Finding
xml.sax.saxutils.escape does not remove characters XML 1.0 forbids. A label or title containing U+0001, U+000B, ESC etc. (common in text pasted from terminals/logs) is emitted verbatim, giving an SVG no browser or XML parser will load; a lone surrogate ("\ud83d" from a truncated emoji escape) renders in the API but makes the CLI die with UnicodeEncodeError when writing.

### Evidence
Repro: flow node text 'a\x01b' -> render OK, xml.dom.minidom.parseString fails 'not well-formed (invalid token)'. `printf '{..\"text\":\"\\\\ud83d\"..}' | drawspec render -` -> UnicodeEncodeError traceback.

### Suggested direction
Refuse (with a pointer) or strip characters outside the XML Char production and lone surrogates during validation.
