### Finding
The validator refuses on per-kind budgets (15 nodes, 16 edges, 25 cells ...) but the generated schema contains `maxItems` once, no minLength/maxLength and no numeric bounds beyond exclusiveMinimum. get_schema is described as returning 'every field it accepts, with types, limits and descriptions', so an agent or editor that validates against the schema gets a pass for a 20-node flow that validate_document then refuses.

### Evidence
`grep -o maxItems schema/drawspec-v1.schema.json | wc -l` = 1 while READABILITY_BUDGET has an entry for all 47 kinds; flow with 20 nodes -> '/nodes/15: 20 nodes is past what one flow can be read at - 15 at most'.

### Suggested direction
Emit simple top-level budgets as maxItems (and text limits as maxLength) from READABILITY_BUDGET in build_schema, and say in get_schema's description which rules remain validator-only.
