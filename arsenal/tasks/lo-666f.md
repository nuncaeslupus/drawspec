**The single biggest adoption barrier.** README and guide both say *not on PyPI
yet* and give `pip install git+https://github.com/nuncaeslupus/drawspec`. An LLM
told "use drawspec" will run `pip install drawspec`, get nothing, and move on —
which is precisely the discovery path this project needs to work.

Checked rather than assumed: `https://pypi.org/pypi/drawspec/json` returns **404**,
so the name is free. There are also **no git tags and no GitHub releases**, so
there is no version anyone can pin.

**This one needs the owner.** Uploading to PyPI is irreversible — a name and a
version number cannot be meaningfully withdrawn — and it needs a PyPI account and
a trusted-publisher or API token that this session does not have. Prepare
everything up to the upload; the upload itself is the owner's to run or to
authorise.

Depends on **A1** (`py.typed`) and **A2** (metadata) — publishing before those is
publishing the version everyone's resolver caches.

## Acceptance gate

A `CHANGELOG.md` with a `0.1.0` entry, a release workflow (or a documented
runbook), `python -m build` output that passes `twine check`, and the version
agreeing in all three places it is written.

```bash
set -e
test -f CHANGELOG.md
grep -q "0.1.0" CHANGELOG.md
python3 - <<'PY'
import re, tomllib, pathlib
version = tomllib.loads(pathlib.Path("pyproject.toml").read_text())["project"]["version"]
init = pathlib.Path("src/drawspec/__init__.py").read_text()
found = re.search(r'__version__\s*=\s*"([^"]+)"', init).group(1)
assert version == found, f"pyproject says {version}, __init__ says {found}"
print(f"version {version} agrees in pyproject and __init__")
PY
uv build
uv run --with twine twine check dist/*
```

## Tests

A test pinning `drawspec.__version__` to the `pyproject.toml` version, so the two
cannot drift — that drift is the classic release-day failure and is exactly what
`pypi-release`'s `validate_release.py` exists to catch. Consider using that skill
rather than reimplementing it.

## Location

`CHANGELOG.md` (new), `.github/workflows/release.yml` (new, trusted publishing),
`pyproject.toml`, `src/drawspec/__init__.py`. Update the install lines in
`README.md` and `docs/guide.md` once it is live — both currently say *not on PyPI
yet* in so many words.

## One extra step at release time, from review of #52

`CHANGELOG.md` deliberately carries **no compare links**. There is no tag to
compare against, so `main...HEAD` compares the default branch with itself and a
link to `v0.1.0` is a 404 — both show a reader nothing, which is worse than an
unlinked heading. A comment in the file says so.

So the release adds them, after the tag is pushed:

```markdown
[Unreleased]: https://github.com/nuncaeslupus/drawspec/compare/v0.1.0...HEAD
[0.1.0]: https://github.com/nuncaeslupus/drawspec/releases/tag/v0.1.0
```

and restores the bracketed headings (`## [Unreleased]`, `## [0.1.0] — 2026-…`)
so the references resolve.

## Everything except the upload is done, 2026-08-17

Prepared from a cloud session, which cannot hold a PyPI credential. What is in
the repository now:

* **`.github/workflows/release.yml`** — tag-triggered. Pushing `v0.1.0` runs the
  suite, checks that the tag, `pyproject.toml` and `__version__` all agree,
  builds, `twine check`s, publishes by **trusted publishing** (no token stored
  anywhere), and cuts the GitHub release. `workflow_dispatch` runs everything
  *except* the upload, so the path can be rehearsed without cutting a tag.
* **The runbook** — `CONTRIBUTING.md` § *Releasing*, including the exact trusted
  publisher fields and the changelog steps.
* Verified here: `uv build` then `twine check` passes on both artefacts, and
  `pypi.org/pypi/drawspec/json` is still a 404, so the name is free.

**What is left, all of it needing a laptop or a browser:**

1. Configure the PyPI trusted publisher (owner `nuncaeslupus`, repo `drawspec`,
   workflow `release.yml`, environment `pypi`). It can be added as a *pending*
   publisher before the project exists.
2. Retitle `## Unreleased` in `CHANGELOG.md` to `## [0.1.0] — <date>`, open a
   fresh `## Unreleased`, and add the two compare links (they are deliberately
   absent while there is no tag — see the runbook).
3. `git tag -a v0.1.0 -m "v0.1.0" && git push origin v0.1.0`.
4. After it lands: update the install lines in `README.md` and `docs/guide.md`,
   which both still say *not on PyPI yet*.

**Do C3 first.** Publishing bakes `SCHEMA_ID` into a released version, and the
new URL does not serve until GitHub Pages is switched on (**C2**). An `$id` in
the wild is no longer a find-and-replace.
