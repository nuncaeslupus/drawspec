**Severity:** medium · **Confidence:** high · **Category:** error-handling

**Where:** `src/drawspec/mcp.py:467-530`

### Finding
_on_call_tool catches only DrawspecError, ValueError and KeyError. Every renderer crash above (IndexError, OverflowError, ZeroDivisionError, AttributeError) propagates out of the handler, which is precisely the 'protocol-level error whose text the agent has to scrape' the module docstring says the server exists to prevent. The blanket ValueError/KeyError clauses also mislabel internal bugs as InvalidArgument/MissingArgument (e.g. KeyError from schema.py:9301 becomes "'from' is required" with no pointer).

### Evidence
Called m._on_call_tool directly: validate_document with the empty-text matrix -> raises IndexError out of the handler; render_document with variants='dark' -> AttributeError: 'str' object has no attribute 'items'.

### Suggested direction
Validate arguments against each tool's input_schema up front, catch Exception last and return the standard refusal shape with error='InternalError', and stop mapping bare KeyError/ValueError from deep inside rendering to argument errors.
