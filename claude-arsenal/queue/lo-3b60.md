# F1: who performs a step — answer issue #48's scannable half

[#48](https://github.com/nuncaeslupus/drawspec/issues/48) is the last open item
from the consumer, and the only one that is a *format* question rather than a
distribution one. **It is entirely doable from a cloud session** — no credential,
no repository setting, no network.

## What was already established, and what is left

The consumer asked for a way to say **who performs a step**. Round five diagnosed
it and the diagnosis was checked rather than assumed:

* A node's appearance has six fields — `shape`, `stroke`, `fill`,
  `fill_pattern`, `dash`, `stroke_width` — of which **four are non-colour**, and
  those four are exactly the ones the greyscale invariant compares.
* All four are already spent telling the eight node roles apart.
* So ownership **cannot be a ninth role**. It needs a fifth channel, or a
  different mechanism entirely.

Round five answered the **content** half with `[box] lead = "rule"`: a line
between a label's two parts, so a box can be a name over what belongs to it.
That was the right small step and it is shipped. It does not answer the
**scannable** half — you still cannot look at a drawing and see, at a glance,
which steps belong to whom. That is what remains, and it is why the issue is
still open.

## Decide before building. Three candidates, and the first is not "add a field"

**Option 0 — `bands` may already be enough, and this is a documentation task.**
Take this seriously before the others, because this project's whole discipline
is that vocabulary opens on evidence. A band already means *this runs alongside
these boxes*, takes an arbitrary member set, and draws a labelled bar beside
them. Declared one-per-actor, that is close to a swimlane already. Try it on the
consumer's actual sheets first. If it reads, the deliverable is a worked example
in the guide plus a reply on the issue — and no new field at all.

**Option 1 — an `actor` field on a node**, drawn in a fifth channel the greyscale
invariant does not already claim: a corner tag, a rule along one edge, a small
set label. Additive, cheap, and it composes with every graph kind. The risk is
that a fifth channel competes visually with the four already in use, which is
precisely what `theme check` exists to catch — extend the invariant to cover it
rather than hoping.

**Option 2 — real swimlanes**, partitioning the layout so each box sits *in* its
owner's lane. The strongest convention for exactly this question, and by far the
largest change: it is a layout-level constraint, not a decoration, and it
interacts with direction choice, groups and routing all at once. Do not take this
on without the corpus evidence that options 0 and 1 fail.

**Bands versus swimlanes is the crux**, and the difference is worth stating: a
band runs *beside* boxes and does not partition, so two bands may cover the same
box; a swimlane *contains* its boxes and is exclusive. Ownership is usually
exclusive, which is the argument for 1 or 2 — and is also exactly what should be
tested against the real sheets rather than reasoned about.

## Acceptance gate

Whichever option is taken, the same two things must hold, and the first is what
makes it an answer rather than a feature.

**Evidence.** At least two of the consumer's real diagrams, redrawn so ownership
is visible at a glance, in `docs/reference/`. A mechanism with no drawing behind
it is the thing `docs/kinds-wanted.md` exists to prevent.

**The invariants still hold**, including greyscale — a new channel that is only
distinguishable in colour fails the rule this project holds every role to.

```bash
set -e
uv run drawspec theme check default
uv run pytest -q
uv run python tools/collisions.py docs/gallery
uv run python tools/clipping.py docs/gallery
```

Regenerate the gallery first (`make gallery`); both checkers must report **0**,
and the suite must stay green.

If option 0 wins, the gate is the same minus any code change — the reference
documents and the guide section still have to exist.

## Tests

Whatever is added needs the treatment `[box] lead = "rule"` got:
`tests/test_theme.py` for the invariant, a kinds test for the geometry, and a
reference document the gallery renders. If a field is added, `make docs && make
schema` and the generated artefacts land in the same diff.

## Location

`src/drawspec/schema.py` (if a field), `src/drawspec/theme.py` (if a channel),
`src/drawspec/kinds/common.py` and `kinds/graph.py` (drawing),
`docs/reference/`, `docs/guide.md`.

**Close the loop.** Whatever is decided, reply on
[#48](https://github.com/nuncaeslupus/drawspec/issues/48) with the reasoning —
including if the answer is "bands already do this". The issue has been open
across two rounds and the consumer is owed the conclusion, not just the code.
