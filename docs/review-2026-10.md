# Review index — October 2026 branch

Everything added on branch `ccr-6186f7c4-lrvt8d`, one row per kind or feature, with the
drawings to open and what to look at in each. Open the SVGs in a browser, in light and
dark mode: the drawings use `currentColor`, so dark mode means the page's ink is light.
`make gallery` puts all of them on one page.

## Open questions for the owner

1. **Self-relations in `entities`** (an employee's manager is an employee, a category's
   parent is a category). They are refused today. Should they get the `states`
   self-loop geometry?
2. **Code spans in edge labels.** A `label` (and so a `states` event) is plain text,
   while `text` carries `` `code` ``. The reference used backticks and they were drawn
   literally (fixed by dropping them). Should labels accept spans too?
3. **Evidence check.** Following the method in [`kinds-wanted.md`](kinds-wanted.md),
   each new kind should be checked against at least two real diagrams it would replace.
   These kinds came from a competitor's menu
   ([coverage survey](proposals/coverage-vs-diagram-design.md)), so the check still
   needs doing, and some figures may turn out to belong to another kind.
4. **Heatmap tones in dark mode** invert in meaning (heavier means lighter). It is
   consistent, but is that acceptable, or should a dark page get a ramp of its own?
5. **Deferred features:** waterfall and wardley wait for a real original. See
   [proposals/README.md](proposals/README.md#deferred-not-proposed).
6. **Slow refusal in `treemap`** (about 2.5 s). Should it fail faster before the fit loop?
7. **`lanes` orientation:** auto mode almost always picks columns at the default width.
   Should the threshold change, or is that the right answer?
